The ask is small, because the build is done. We need three things. One: a data partner willing to run the pipeline on a de-identified extract, under its own approvals; the code is built to run unchanged on a real extract, and nothing leaves their environment. Two: four gum specialists, about a day each, to label the validation charts independently; that is the 31 hours on the previous slide. Three: a few days of GPU time, for the larger models. In return: we publish the acceptance-test result, good or bad, with the code. If it works, gum disease becomes something you can count across clinics, in the same format as the medical record, so the link with diabetes can be studied at scale; and the same reader becomes a way to check AI answers against the record, which is the other path on the landing page. No partner has been contacted, and nothing here is any organization's plan. If asked what could go wrong: real notes are harder than synthetic ones, and the AI may not pass; that is still a publishable answer.
