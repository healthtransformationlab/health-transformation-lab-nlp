# Feature Specification: publish the synthetic data, results and best model on Kaggle

**Feature Branch**: `feat/120-018-kaggle-publish` (opened as 018; renumbered to 020 because spec 018 is gold naming)

**Created**: 2026-10-28

**Status**: draft

**Input**: "Publish the useful datasets to Kaggle, same with models, and a collection; public, since the repo is
public." Decisions: datasets under CC BY 4.0; the best encoder only as a model; results as a separate
dataset; public from the start.

> Personal learning project; synthetic data; public sources only (`DISCLAIMER.md`). Everything published is
> generated by this repo. Nothing from `data/external/` (others' datasets: link, don't re-host), no
> `simulated_*` files (they would read as results), no MedGemma weights or adapters (HAI-DEF terms).

## User stories

### US1 - The synthetic notes and charts are a public Kaggle dataset (P1) #120

Anyone can download the 3,484 synthetic training notes with labels, the structured visits, and the
240-note review set with its answer key, with a data card that says what it is and is not.

**Acceptance**: `kaggle/publish.py --dataset notes` builds a folder whose files are exactly the listed ones,
with `dataset-metadata.json` (CC-BY-4.0, title and subtitle within Kaggle's limits) and a card carrying the
disclaimer; the `kaggle-publish` workflow creates the dataset public the first time and adds a version after.

### US2 - The benchmark results are a public Kaggle dataset (P1) #121

Every real model's predictions on the 240 review notes, the LLM run details, the ladder scores and the judge
outputs, so others can compare without rerunning. Labelled as measurements on synthetic notes, not evidence
about any product.

**Acceptance**: as US1 with `--dataset results`; no `simulated_*` file is ever included.

### US3 - The best note classifier is a public Kaggle model (P2) #122

The class-weighted ModernBERT-base encoder (the leaderboard's best fine-tuned encoder) in transformers format,
with a model card giving its scores on the review set from the same run.

**Acceptance**: the encoder notebook can keep a fine-tuned model's weights as output; the workflow trains it
on Kaggle and publishes it as a model instance (Apache 2.0, the base model's licence). Separate pull request.

### US4 - One place to start: a Kaggle README and a collection (P2) #123

`kaggle/README.md` explains the notebooks, workflows, datasets and model in one page; the collection on
kaggle.com groups them (Kaggle's API has no collections, so its steps are in the README). Kaggle collections
turned out to be private lists with no public setting (#270), so the README's table is the shared index and the
collection is the owner's own list.

## Requirements

- **FR-001** Files to publish are named in code (`kaggle/publish.py`): listed, or globbed inside named folders
  with `simulated_*` dropped, never from the whole tree. A test fails, and the build refuses, if a file is
  missing, simulated, under `data/external/` or `data/raw/`, holds a `sim:`/`calib:` row, or is a prediction
  file that isn't a full run of the review notes.
- **FR-004** A refused upload fails the workflow (the Kaggle CLI only prints it): uploads go through the Python
  API and its status is checked.
- **FR-002** Cards are markdown files in `kaggle/cards/`, reviewed like code; each states: synthetic, personal
  learning project not affiliated with any organization, not for clinical use, how it was generated (link to
  the repo), licence, and how to cite.
- **FR-003** Publishing runs from GitHub Actions (`kaggle-publish.yml`, environment `dev`, the same Kaggle
  secrets as the notebooks), never from a laptop, so every version matches a commit; the version message
  names the commit.

## Success criteria

- SC-001 Both datasets exist on Kaggle, public, CC BY 4.0, matching the repo's files at the published commit.
- SC-002 Nothing simulated, external or real is on Kaggle.
