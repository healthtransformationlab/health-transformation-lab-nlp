# PR Review: 029 US9: a planned periodontal extraction counts as tooth loss only when the tooth goes missing later

## Summary
The tooth-loss model's `completed_planned` label set no longer counts a planned periodontal extraction whose tooth is
still in the mouth. A planned extraction now counts only when the tooth is recorded missing at a later visit within
`ModelParams.planned_window_days` (365) of the plan. The earlier rule stays as a sensitivity setting
(`--planned-window-days none`). The synthetic extract gains later-missing teeth to exercise the rule; the tooth
table, the stage recount, script 51, the R twin, spec 029 (US9, FR-013, SC-011) and the analysis plan follow. The
review found one real generator bug (a tooth already extracted could also be recorded missing later), fixed on the
branch with a regression test, plus minor points, most fixed. CI is green, the full suite and R parity pass locally.
Verdict: approve with nits; one naming question waits for the owner.

## Findings
### 🔴 Blocking (Critical)

### 🟡 Should fix (Important, non-blocking)
- **Fixed in afa8f69.** `open_dental.py`: a tooth with a never-done plan could be extracted on a later plan and then
  also be recorded missing by the old plan; `chart_quality` then subtracted it twice from the expected teeth.
  Reproduced at 300 patients, seed 6 (patient 189, tooth 2). Fixed: the old plan records nothing when its tooth is
  gone, and `chart_quality` counts each lost tooth once. Regression test
  `test_a_tooth_already_extracted_is_never_recorded_missing_later`. The 6,000-patient results are unchanged by the
  fix (verified by rerunning both rules).

### 🔵 Nits / suggestions (Minor)
- **Fixed.** Python compared a later loss with the first visit by timestamp, R by day; a time on the first-visit day
  split them. Both now compare by calendar day (`tooth_loss._statuses`, `open_dental._recorded_later`); test
  `test_later_missing_edge_cases`.
- **Fixed.** Two edge cases had no test (a plan after the loss; an undated entry row with a dated later one): added.
- **Fixed (documented).** In the stage recount an in-window planned-then-missing tooth gets the completed + planned
  model's own probability, which is in-sample. `docs/tooth_loss.md` now says so. Counting such teeth as recorded, or
  scoring them out of fold, is a possible follow-up.
- **Fixed.** The `Params.planned_then_missing` comment overstated the random stream's isolation: the teeth it removes
  change later draws.
- **Owner decision.** `plan_to_missing_days` uses a `_days` suffix, which AGENTS.md's column table doesn't list. The
  table is silver, so `test_sql_conventions` doesn't check it. Either add `_days` to the table (a rules change, the
  owner's) or rename before the column reaches gold.
- **Not fixable now.** Tests and code landed in one commit (46350c8); the tests were written and seen failing first
  in the session, but the history doesn't show it.
- **Follow-up.** The silver ERD PNGs weren't re-rendered (the draw.io web app isn't available here); the `.drawio`
  sources and data dictionary are current.
