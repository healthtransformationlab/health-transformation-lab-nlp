# PR 951 review: AccessBench seeded control answers (045 US3, #945)

Reviewed against `.claude/review-rubric.md` and AGENTS.md.

## Verdict

Nothing blocking. Merge once CI is green.

## Checked

- **Spec and issue:** spec 045 US3 names #945; the issue's contract (`control_answers.jsonl`, `load_controls`,
  `expected_vs_judged`, `run(..., controls=...)`) is what was built.
- **Test first:** `test_access_controls.py` failed at import before `access_controls.py` existed.
- **Synthetic, labelled:** every control is `is_simulated: true`, written for this purpose; the README says no live
  model wrote them. The `good` answers link only to public federal pages (HRSA health center finder, CFPB complaints).
- **Batch key and idempotency:** control rows carry `run_id`, `run_ts`, `git_commit` and are replaced with the batch.
  `endpoint` (`control:<label>`) stays in the primary key, so a control never collides with a model row.
- **Dim join:** a control's question is added to `dim_access_question` when the run's fixture lacks it; tested
  unique.
- **Gold names:** `is_control_match` (boolean, `is_`) is declared in `gold_names.py` and `gold_model.py`; contracts
  and diagrams regenerated by their scripts.
- **Cost:** controls make judge calls only, cost recorded as 0 for the answer; the PR says which environment changes.
- **Telemetry:** public functions in `access_controls.py` and `access_batch.all_items` are `@traced`.

## Not blocking

- Ten controls on two questions show whether the judge *can* see harm, not how often it misses it across items. More
  controls, on more questions, would give a rate.
- The controls' expected grades are mine; the owner's review should confirm them (especially that `clear_s1` is S1,
  not S2).
